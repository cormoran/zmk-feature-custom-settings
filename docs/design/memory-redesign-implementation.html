01 · この実装で変わったこと

既存の RPC schema と Flash の保存名・encoding を保ち、値の格納層を置き換えました。提案の最終形へ一度に API を切り替えるのではなく、既存 consumer が使う descriptor API を adapter として残しています。

実装済み
  • INT32 / BOOL / BEHAVIOR 配列を型のサイズで格納。dirty / persistent は bitset。
  • 配列既定値を型付き ROM 配列に変更。可変長要素は ROM slice と pool node。
  • plain blob と可変長配列要素が共通予算を使用。未変更 blob は ROM 参照。
  • address 順の intrusive list による線形 compaction。
  • keyspace の常設 ordinal 文字列を廃止。世代付き参照を通知・chunk に導入。
  • 同期編集の workspace 共用と単一設定 PERSIST の失敗時旧値保持。
  • PR #59 の RPC callback 化・共有応答・central 不要領域除去と relay 制約保持。
この互換段階で残しているもの
  • 互換 ON の旧 descriptor/default/constraint、runtime default pointer。OFF は compact 表現。
  • 旧 C API 向け array view cache（互換 OFF で除去）と keyspace slot descriptor。提案の 16 B slot ではありません。
  • chunk session の専用 buffer。設定 lock はフレーム間では保持しません。
  • Flash I/O 中の settings lock。専用 worker・admission への全面移行は未実装です。
  • 同一値の途中更新を検出する version、disconnect/timeout による session 解放は未実装です。
  • 配列・scope の全体 rollback、実機での stack high-water 測定。

総予算 CONFIG_ZMK_CUSTOM_SETTINGS_POOL_SIZE は既定 512 B。すべての設定の最大値を同時に保持する保証ではありません。容量不足は -ENOSPC。独立した予約が必要な consumer は既存の _POOLED / _SIZED を使用できます。

03 · 常設 carrier をなくす

型RAM / 要素（ARM32）ROM default / 要素
INT324 B4 B
BOOL1 B1 B
BEHAVIOR12 B12 B
STRING / BYTESblob node 12 B ＋ 変更済みの payloadslice 8 B ＋ payload

配列 default の登録形式は C API の変更点です。ARRAY_DEFAULT_INT32_DEFINE を使う既存コードは呼び出し方を変えずに移行できます。手書きの carrier 配列は default-only adapter で識別して読めます。ROM も削減するには、親の型に合う raw 配列へ移行します。

static const int32_t defaults[] = {10, 20, 30};
// STRING/BYTES の場合は slice 配列。
static const struct zmk_custom_setting_slice labels[] = {
    {.data = "alpha", .size = 5}, {.data = "beta", .size = 4}
};
配列の insert/remove で特に読むところ

新要素は先に非 active な tail に書きます。容量不足なら active な要素と長さは変わりません。成功後に node の所有権を swap して index をずらします。has_persistent は Flash の ordinal に対応するため、payload と一緒にずらしません。変更対象の dirty bit は立てます。

04 · allocator の不変条件

管理 node / ROMlive bytes編集 workspace
others = pool_used - target.extent
if new_extent > pool.size - others:
    return -ENOSPC     // node・byte・flags・TEMPORARY はそのまま
snapshot(input)       // 別の node 内の input も移動前に確保
reserve → compact → copy → size / flags を公開

コードでは snapshot を容量検査より先に行っても、変更するのは独立した workspace だけです。allocator の失敗は live データに影響しません。pool は 65,535 B 未満で、extent は 16 bit。任意 heap allocation は使いません。

満杯のときの置換を試す

512 − 64 ＋ 64 = 512 B。置換可能です。

最終 live 容量の試算。workspace の必要量、STRING の NUL、Flash backend は別の制約です。

05 · 「同じ slot」でも「同じ設定」とは限らない

struct zmk_custom_setting_ref {
    const void *owner;     // static descriptor / array parent / keyspace
    uint32_t index;
    uint32_t generation;
    enum ... kind;
};

ref は ARM32 で 16 B。可読性を優先して kind を明示しています。ref_visit() は settings lock 内で identity を検証し、array なら stack 上に一時 descriptor を作ります。callback 外へ descriptor を持ち出しません。

配列 ref は index を指す

insert/remove 後も index 自体は同じです。その位置の値は変わります。active length の外なら -ENOENT。32 個以上の ref を保持しても view cache の枠を消費しません。

TEMPORARY の owner も安定化

所有者は scalar state、または array state＋index。旧 view cache が再利用されても overlay は残り、rollback または範囲外への縮小で解放されます。

旧 find_array_element() の返り値は引き続き短命な borrowed pointer です。保存・遅延処理には直後に ref を capture します。keyspace slot の public な descriptor 自体もまだ互換用に残っています。

chunk commit も ref を解決した lock 内で permission を再検査し、同じ write API へ接続します。複数フレームの間は設定 lock を保持しません。別 writer による途中更新の競合検出と worker への委譲は、今回の実装範囲には含みません。

07 · 同時に生きる buffer を隠さない

通常の record read は ROM / pool slice を lock 中に decode するため、大きな局所 buffer を使いません。TEMPORARY 値も compact view で参照。main stack の設定値は変更していません。

互換性を外せる境界

CONFIG_ZMK_CUSTOM_SETTINGS_LEGACY_COMPAT は既定 ON。OFF でも配列・keyspace・保存・RPC を使えます。旧 API の利用側を移行した後で OFF にします。

ARM32 の構造体 / 領域ONOFF
zmk_custom_setting52 B40 B
zmk_custom_setting_state20 B共通 flags は 1 B。型別の総量は下表
array_state36 B32 B（legacy 判別なし）
array view cache旧 lookup 利用時は既定 896 Bコード・領域とも除去
zmk_custom_setting_value76 B8 B：value_view への別名（定義は一つ）

共通処理は ON/OFF とも 8 B の value view を使用。76 B の owning carrier は互換 ON の入口と旧 default / constraints に限定します。常駐 scratch は 2 × 76 B → 2 × 8 B。default / constraints は ROM 配置なので、その縮小は主に Flash に効きます。

移行時には、旧 carrier 配列 default → 型付き配列、借用 view → stable ref、set_default → 不変 default、手書き store → 標準 pool 登録へ変更します。DYA2 の現在の consumer は旧形式を使うため ON で確認しています。OFF 比較には同じ設定内容の専用 fixture を使用し、機能を減らした結果と混同しません。

安全性：RPC の制約 callback は stack 上の array view を保持せず、永続的な親 descriptor を保持します。テストでは encode 前に一時 view を上書きしても、メタデータが失われないことを確認します。

RPC は converter がない値を lock 中に直接 encode。converter がある場合は必要な payload buffer を明示的に確保し、従来どおり lock の外で呼びます。予約済み thread stack 容量は減らしていません。

state.h が型別領域と accessor を定義。互換 ON では compat/state.h の旧 20 B union を維持します。keyspace は常に blob state を持ち、その中の payload の型とは区別します。

08 · RPC：最大容量をメッセージごとに常設しない

PR #59 の RPC 最適化と relay 回帰修正を統合。前段の typed storage とは別の削減です。従来は SettingMeta.constraints[8] に各制約の options / labels が内包され、応答・通知・relay に約 7 KiB ずつ複製されていました。protobuf の field number と wire format は維持します。

領域統合前 → 統合後 (ARM32)担当コード
custom-settings 応答7,012 → 264 B（shared）custom_settings_studio_helpers.c
通知7,020 → 272 Bcustom_settings_handler.c
relay 通知 decode envelope7,056 → 44 B
peripheral 用 relay 応答7,012 B → central では除去
relay の制約を捨てない

callback field は decoder を設定しないと読み飛ばされます。受信した制約を relay frame 上限の encoded scratch に保持し、再送時に書き戻します。INT32 / STRING の通知について、制約込みの wire が往復で一致する回帰テストを移植しています。

共有応答の寿命

Studio の 1 request → encode → 次 request という直列処理が前提です。generation は古い encoder を拒否しますが mutex ではありません。他モジュールの独自バッファは自動では共有化されません。API の契約を参照。

変更点：SettingMeta constraints の FT_CALLBACK、relay notification の FT_CALLBACK、共有応答の世代・容量テスト。#59 の別方式の compact storage API は導入せず、本実装の typed storage を維持しています。

09 · 測定・検証

同じ board xiao_ble//zmk / shield tester_xiao、同じ共有 West profile、同じ build matrix で比較しています。新しい Kconfig の pool 予算は差分の一部です。

測定方法：ELF の _image_ram_size と _flash_used（Zephyr リンカーの Used Size と一致）。RAM は静的確保・予約済み stack / heap と alignment を含み、実行時 high-water ではありません。通常の size の data には Flash に配置された iterable section も含まれるため、data + bss は使いません。差分は新 − 旧です。

10 · コードを読む順番

  1. pool.h：extent == 0 が ROM 借用を表すこと。
  2. allocator.c：失敗判定が mutation の前にあること、list が常に address 順であること。
  3. blob.c：input が pool 内でも移動前に snapshot されること。
  4. array_storage.c → array.c：型と lifecycle の分離、insert/remove 時の node swap と persistent flags。
  5. ref.c：array index と keyspace generation の異なる寿命契約。
  6. custom_settings.c：persist_raw_candidate_locked、write_value_locked、default/load。
  7. RPC handler：notification queue と chunk commit の ref 解決、lock の順序。
  8. テスト：test_memory_redesign の観測結果と失敗注入。

移行上の注意：public struct の内部を直接読む consumer は再ビルドが必要です。配列 default は型付き表現を推奨（旧 carrier 配列も adapter で対応）。slot の ordinal_name と state の temp_slot は廃止。通常の getter/write/keyspace API と RPC/Flash の wire format は維持しています。
